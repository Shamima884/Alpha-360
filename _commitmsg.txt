fix: admin panel login card renders under admin_server

admin/index.html referenced its own script as ./js/admin.js. When
admin_server serves the panel at the repository root (/), ./js/admin.js
resolves to /js/admin.js, which is not in the allow-list, so the browser
refused to execute it (MIME text/plain) and the login card never rendered
(1482-byte static skeleton).

Switched admin/index.html to root-absolute asset paths
(/shared/*, /admin/js/admin.js) which resolve correctly whether the page
is loaded at / (admin_server) or /admin/ (full project). All of these
paths are already allow-listed and served (200).

- shared/js/api.js: default backend mode 'google' -> 'local'.
- admin/js/admin.js: make the DOMContentLoaded boot non-blocking (render
  first, take the backend snapshot in the background).
- _renderuitest.ps1: reset the Chrome profile each run for a cold,
  deterministic cache.
- shared/README.md, admin/README.md: document admin's root-absolute paths.

All four suites green: _selftest (student), _facultyui (faculty, 52KB),
_rendertest (admin matrix, 26/26), _renderui (admin login card, 3232 bytes).
